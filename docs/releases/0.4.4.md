## 0.4.4 — Resource Guard

Instale o binário desta release. Não use um `go build` local na VPS nem no Forge: substitua `.mithril/bin/eregion` pelo asset da tag `v0.4.4`.

```bash
VERSION=0.4.4
REPO=EreborCodeForge/eregion
curl -fsSL -o eregion \
  "https://github.com/${REPO}/releases/download/v${VERSION}/eregion-linux-amd64"
curl -fsSL -o checksums.txt \
  "https://github.com/${REPO}/releases/download/v${VERSION}/checksums.txt"
sha256sum -c checksums.txt --ignore-missing
chmod +x eregion
./eregion version
```

O contrato de versão continua:

```text
eregion 0.4.4
protocol eregion/1
```

### O que mudou

- `resource_guard` distingue capacidade pedida, alvo da política, workers admitidos e workers reais. O padrão é `observe`: o plano é publicado e a contagem segue o caminho anterior.
- `enforce` recusa processos novos que não cabem no orçamento, inclusive no boot. Não mata worker ocupado nem abre outro sinal de drenagem.
- `hard_limit_mb` é orçamento de admissão. Não grava `memory.max`, rlimit nem cgroup.
- O ledger reserva o custo antes do spawn, substitui essa reserva pelo RSS na amostra seguinte e bloqueia só admissões novas se o RSS dos workers já admitidos crescer.

### O que não mudou

Protocolo `eregion/1`, estratégias de scaling, intervalo padrão de coleta e os limites de admissão. `off` continua no reconciler anterior. A tag `v0.4.3` já estava publicada e não foi reescrita.
